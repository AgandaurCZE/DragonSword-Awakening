## How the site works · updated 10 Nov
- One static page in three parts (split on 10 Nov): `src/index.html` (layout, ~18 KB), `src/css/site.css` (every style, ~100 KB; asset paths start with `../`) and the numbered scripts loaded in order: `01-core` (globals, `$`, `absUrl`), `02-teams-karma`, `03-profile`, `04-gear-builds` (JS port of `tools/hero_stats.py`), `05-tierlist-heroes-patches`, `06-dungeons`, `07-tierlist-v2-cookbook` (public tier list), `08-finder-guides`, `08-items-tools-guides`, `08-site-search`, `08-steam-news`, `09-startup` (runs last). **No guide data** in any of them. The files share one global scope, so code that runs at load time may only use what earlier files define; everything else runs after the last file. **Bump `?v=` in `index.html` for any CSS or JS file you change** (GitHub Pages lets browsers keep a copy for about 10 minutes). **Image paths written into CSS variables from the script must go through `absUrl()`**, or the browser resolves them against `src/css/`. Hosted on GitHub Pages from the root of `main`: https://agandaurcze.github.io/DragonSword-Awakening/. No framework or application server; a small assembly step copies committed sources into the public layout. Since 11 Nov a GitHub workflow runs every check on each push and publishes only when they pass (Checks and publishing, below); the published site contains the committed sources assembled into their original public paths. `src/js/` and `src/css/` are formatted with Prettier since 11 Nov (one statement or declaration per line).
- Start-up: `src/js/09-startup.js` fetches `data.json` with `cache:'no-cache'` (since 10 Nov: the browser revalidates every visit, so it's always current but only re-downloads when the file changed; before, a `?v=` timestamp and `no-store` forced the full 712 KB every time), copies every top-level key into a global of the same name, then calls `startApp()`, which draws every tab (`renderTeams()`, `renderKarmas()`, `renderHeroes()`, `renderGear()`, `renderPatches()`, the simple pages, `renderTierV2()` …). That drawing takes about 85 ms (measured 10 Nov). Normal Dungeons draws and the 45 dungeon banners preload only when a Dungeons page is first opened (until 10 Nov the preview waited for all ~9 MB of banners before drawing anything).
- All enabled menu pages are public Beta pages. Root is Shortcuts. `SITE.routes` defines clean paths, including `/news` for official Hound13 announcements.
- At 760 px and below, a sticky top bar and labelled menu replace the permanent icon rail. Shortcuts features the Tier List, Teams, and `/finder`, with a link to the latest Hound13 announcement.
- `src/js/08-site-search.js` indexes names and selected metadata from the public site data. The search dialog opens from the desktop rail, the mobile header, `/` or `Ctrl/Cmd+K`. It loads the Item Database tabs on first open through the shared item loader. Gear sets use `gear#set=<name>`, Karma cards `karma#card=<name>`, Cookbook recipes `cookbook#recipe=<id>`, and exact Item Database entries `items#item=<tab>:<name>`, with values URL-encoded.
- The Cookbook pantry reuses visible recipe combinations, ingredient options and the star calculation. It counts each slot against the selected quantities and offers the highest-star listed combination that can be made, or a combination with one missing ingredient. Quantities are held in memory for the current page load. Saved cooked marks still use the existing Cookbook progress storage.
- The Finder reads encounter art, difficulties and weaknesses from `TIER_LIST_V2.bosses` and tower statuses from `TOWER_TRIALS`. It links to encounter-specific rankings and to standard or recorded Teams lineups. The Guides library reads `GUIDES.categories`, and the individual guides open through `guides#<id>`. Getting Started is featured under New Players and linked from Shortcuts. Its section links open directly via `guides#start-here-<section>`. The three mechanics quick links appear above the Getting Started article. Planned cards are labels. The three mechanics articles are in `src/js/08-finder-guides.js`. The dungeon, boss, tower, gear and progression articles are in `GUIDES.articles` and use the same renderer. Guide and Shortcuts cards share `cardEmblem()` and `assets/ui/card-emblems.svg`. Named encounters reuse the existing boss portraits and tower crests. The guide renderer matches `TEAM_DATA` lineup names in prose and uses the shared reference popover for mini rosters. Team links preserve the `#team=` target in the URL. Finder encounter and difficulty, boss and tower ratings, Ursula speed runs, hero tabs and exact skill links also retain their selections in the URL. On touch screens, an info button opens the team roster or skill preview while the link opens the page.
- **Public Beta:** launch approved by David on 11 Nov. The runtime preview gate and old public tier list are removed. Old query/hash links remain compatibility aliases. Routing and generated GitHub Pages entries are documented in DATA_REFERENCE, "Public Beta routing and Shortcuts".
- Item Database and Achievements load `assets/items/*.json` when opened.
- Test locally with `python3 tools/serve_site.py` (file:// fails). The checks are scripts since 11 Nov: `python3 tools/check_all.py` before every commit, and `python3 tools/public_diff.py` (the pixel check) for any change to the page files; see Checks and publishing below. Then look at the changed tab yourself.

## Data structure · 9 Nov
- `data.json`: **all guide content**, UTF-8, 1-space indent, `ensure_ascii=False`. Never rename keys. Key groups (full shapes in DATA_REFERENCE):
  - Heroes: `HEROES`, `CHARACTER_PROFILE_DATA`, `AWAKENINGS`, `HERO_BASE_STATS`, `HERO_STAT_MODEL`, `HERO_BUILDS`, `SKILL_LEVEL_MULTIPLIERS`, `SKILL_BUFF_LEVELS`.
  - Tiers and teams: `TIER_LIST_V2` (preview), `TOWER_TRIALS`, `TEAM_DATA`, `TIER_ORDER`, `TIER_COLORS`.
  - Karma: `KARMA_DATA`, `KARMA_ASCENSION`, `KARMA_LEVELLING`, `GENERIC_KARMA`.
  - Gear: `GEAR_DATA`, `GEAR_STATS`, `GEAR_UPGRADE`, `RUNES`.
  - Mechanics: `DEFENSE_MODEL`, `DAMAGE_CALC`, `STATUS_EFFECTS`, `LEVEL_COSTS` (formulas explained in [GAME_MATH.md](GAME_MATH.md)).
- `data/research.json` (10 Nov): research the page never shows (`DAMAGE_TESTS`, the training-dummy results behind GAME_MATH). Visitors don't download it; the validator checks it parses.
  - Other pages: `DUNGEONS`, `TRAIT_DUNGEONS`, `FAMILIARS`, `TITLES`, `COOKBOOK`, `GUIDES`, `PATCH_NOTES`.
  - Shared: `meta`, `schemaVersion`, `ARCHES`, `ARCH_COLORS`, `STATUS_ARCHETYPE`, `ROLE_ICONS`, `UI_ICONS`.
- `assets/`: images and source notes by topic (heroes, karma, gear, items, bosses, dungeons, tower, raid, roles, ui, upcoming …). Portraits are `.webp`; delete David's source PNGs after cutting.
- `tools/`: `validate_data.py` (run before every commit), `hero_stats.py` (base stats and builds; run without `--write` first), `skill_meta.py --write` (after editing skill text or Karma/gear sentences), `tools/image/` (codex card cutting: `codex_recolor.py <karma|familiars|heroes> <file.webp,...>` matches each card in David's screenshots in `assets/<kind>/*.png` to the existing card by shape and overwrites the named ones, using `detect.py` `cards()` and `final.py` `clean()`, which paints out the printed name; afterwards set `owned: true` in data.json and delete the PNGs).
- `docs/`: notes (this library) and the artifact sources and backups in `docs/testkit/`.

## Checks and publishing · 11 Nov
The rules are AGENTS.md, "Golden rules". This is how the machinery works. Everything is a plain script in `tools/`; the source folders are assembled without transforming site content.

| Script | What it proves | When it fails |
|---|---|---|
| `tools/check_all.py` | Runs everything below in order and prints one line per check. Run before every commit. `--no-browser` skips the browser part; `--base REF` compares cache numbers against another commit. | Fix the named check; don't commit. Exit 2 = passed but the browser part couldn't run. |
| `tools/validate_data.py` | Names, numbers and image paths in data.json make sense (existing rules). | The message names the entry. |
| `tools/check_shape.py` | Every key in `data.json` and `assets/items/*.json` is one recorded in `tools/data_shape.json`, at the right level, with the right type; no field that every sibling has is missing. | A typo: fix the data. A key you added on purpose: document it, then `--update` and read the printed differences. |
| `tools/hero_stats.py` (no `--write`) | `HERO_BUILDS` and `HERO_BASE_STATS` are what the optimiser gives from the current tables: it must print `No changes.` | Inspect the listed changes, then `--write`. |
| file rules (in `check_all.py`) | LF line endings; data.json in its format (UTF-8, 1-space indent); every `src/js/` and `src/css/` file is loaded by index.html, in order, with `?v=`. | The message says which file. |
| `node --check` | Every `src/js/*.js` parses. | Syntax error with line number. |
| cache numbers (in `check_all.py`) | A css/js file that changed since the last commit has a new `?v=` in index.html. | Give that file's link a new `?v=`. |
| `tools/check_site.py` | In a headless browser, on the public URL and `?tiers=new`, at 1400 px and 390 px: every menu page at both widths, all 20 hero profiles with their three tabs at 1400 px, and Ryza/Sion/Alex profiles at 390 px with no console error, script error or missing file; public Beta home, all clean direct routes and reloads, unified hero/tier URLs, Back/Forward and old aliases; backup/restore download, review, cancellation, undo and failure recovery at both widths; `optBest` reproduces every stored build; `gmBuild` equals `tools/team_gear.py` on nine builds (`GM_CASES`, including A3 and A0 account cases). `--quick` = 3 heroes, no parity. Also (12 Nov): the tab icons are downloaded and decoded (64 and 180 px); tab names; boss header art; boss rewards by difficulty. Also (13 Nov): the Damage Calculator's Hunt boss readings; the tier list's Awakenings toggle and its boss tab rows (no "All bosses", Hunt above Raid); no page shows the name "David", the Teams page rows and toggle, and the tower Counter marks (`visible_text_rules`); the Karma level picker against the stored tables for all four stat types at all 75 levels. **One approved exception (David, 12 Nov):** a cancelled download (`net::ERR_ABORTED`) of exactly `assets/ui/favicon.png` is not a failure, because full Chrome sometimes cancels it when the check moves on; every other failure still fails, and the exception is self-tested on every run (`aborted_favicon`, `icon_checks`). Don't widen it. | `FAIL` lines say the URL, width, what happened and, for failed requests, the browser's reason. |
| `tools/build_routes.py --check` | Every committed clean-route shell exactly matches src/index.html with the correct relative asset base; no obsolete entries remain. | Regenerate with `python3 tools/build_routes.py`. |
| prettier (warning) | `src/js/` and `src/css/` are in the agreed format (`.prettierrc.json`). | `npx --yes prettier@3.9.10 --write src/js src/css`. |
| `tools/public_diff.py` (not part of `check_all.py`; golden rule 4) | Every public page and hero profile renders the same as in the last commit, pixel by pixel (42 views with `--quick`, 87 normally, 194 with `--preview`). A colour step of 1–2 of 255 is ignored and a differing view is rendered twice before it's reported. | It lists the views, how many pixels and where, and keeps before/after pictures. Acceptable only if it's exactly what David asked for. |

- **Needs:** Python 3, Node (for `node --check` and `npx prettier`), and for the browser checks `pip install playwright` plus a Chromium (`python3 -m playwright install chromium`) or an installed Chrome.
- **Publishing:** `.github/workflows/deploy.yml` ("Check and publish") runs on every push to `main`: it installs Playwright, runs `check_all.py`, and only if that passes assembles a clean `git archive HEAD` with `tools/build_site.py` (generated URL entries at the public root, code at its existing public paths, assets/data/notes preserved) and uploads that artifact and publishes them to GitHub Pages. The Pages source is set to "GitHub Actions" (David, 11 Nov; before that GitHub's Jekyll built the site straight from the branch, with no checks). A failed run publishes nothing: the live site stays on the last good commit. Publishing takes about 1–2 minutes from the push (1 min 14 s on the first good run). To publish again without a new commit: Actions tab → Check and publish → Run workflow.
- **Seeing the result:** the repository's Actions tab, or `gh run list -R AgandaurCZE/DragonSword-Awakening -L 3` and `gh run view <id> --log-failed`. The run page shows the full `check_all.py` output in its summary. If api.github.com is blocked by the environment, the normal `github.com/.../actions` run page may still be readable: match the run to the exact commit and read its visible Status and publish job. This fallback verified 92a4e43 on 11 Nov; signed-out log access remains limited.
- **Format:** `src/js/` and `src/css/` are formatted with Prettier 3.9.10 since 11 Nov (one statement or declaration per line). Long lines that remain in `src/js/` are template strings holding HTML; split one only while changing that code, and prove it with `public_diff.py --preview`.
- **When a check itself needs changing** (a new parity case, a new data file, a new kind of view): do it in the same commit as the change that needs it, say so in CHANGELOG, and never loosen a check to get a pass (golden rule 3).

### Steam announcement refresh

- `tools/steam_news.py` reads the full official Steam community announcement history for app 4570720 and writes `data/steam-news.json` atomically. Only Hound13-authored announcements are used. Titles beginning with `Update Notes x.x.x` go to Patch Notes. The News page shows other announcements in full, four at a time, newest first.
- The browser renders Steam markup as DOM nodes and restricts external links to HTTPS. YouTube embeds and links show a thumbnail, a click-to-play overlay and an original-video link. The patch timeline keeps the curated entries and opens full bodies from Steam, with archived source notes as the fallback.
- Hero links on Teams open Build and Teams using `#build` on direct arrival. Linked skill names show the shared profile card and slider, and `#skill=<name>` opens the named skill on direct arrival. Sidebar destinations, hero portraits and signature-owner links support the browser’s normal new-tab and new-window commands.
- **Skill values follow the patches (15 Nov 2026):** after fetching, the workflow runs `tools/apply_patch_skills.py`. For every balance patch newer than `meta.balancePatch`, each recognised before → after row updates that skill's "Attack Power N%" text and `meta.attackPct` (only if the skill still shows the old value, within 2; otherwise it's printed as skipped, never guessed), then `meta.patch` / `balancePatch` move up and `tools/hero_stats.py --write` refreshes the stored builds. Ratings are never changed: a hero changed after `meta.tierReviewedPatch` gets a dashed tier chip and a hover line (`v2PatchedSince()` in `07`) until David reviews the tier list and `meta.tierReviewedPatch` is raised.
- The half-hourly refresh workflow also has a manual trigger. It commits only a changed feed and dispatches the existing check-and-publish workflow because the bot's push does not start push-triggered workflows. An importer failure leaves the last published feed in place.
- Numeric versions sort by their components. The header shows the newest game patch. Hero arrows use the newest balance patch. The Tier List and hero tier summary show the explicitly reviewed balance version. Historical version references retain their dates and versions.
- Recognized before/after skill coefficients enter the existing patch row and percentage display. The combined hero percentage requires complete numeric coverage of the hero's damaging skills. Text-only changes keep their descriptions. Curated patch entries preserve their hand-checked rows and annotations.

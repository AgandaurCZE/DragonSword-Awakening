## Dungeons pages (public Beta)

- Public collapsible Dungeons group: `/dungeons/normal`, `/dungeons/trait`, `/dungeons/currency`. Bare `/dungeons` returns to Shortcuts.
- **Normal Dungeons:** 15 cards grouped by `farmGroups`; each card keeps its own I/II/III choice, shows that difficulty's rewards and the matching banner from `assets/dungeons/banners/`. Rewards are `[itemKey, amount]` pairs resolved through `DUNGEONS.rewardItems` (EXP included); set icons come from `GEAR_DATA`. The original design and artwork foundation are David's, made with ChatGPT.
- **Currency Dungeons:** all five discovered cards with I/II/III; no undiscovered cards remain; leaving the page resets them to I. Rewards resolve through `currencyRewardItems`. Each of the five cards uses a shared banner across all three difficulties. The frame is a separate overlay; the background sits 9 px inside it with an 8 px radius.
- **Trait Dungeons:** unchanged data and rendering, plus nine preview banners (three Mantius, two Drosophia, four Ghagaroach).
- `openDungeons({set, material, slot})` is the cross-page entry point (used by the Gear page's set links). Available on the public Beta site.
- Banner art rules: [DUNGEON_ARTWORK_WORKFLOW.md](DUNGEON_ARTWORK_WORKFLOW.md).

## Public Beta routing and Shortcuts (11 Nov 2026)

`SITE` is `{stage, logo, routes, toolRoutes, shortcuts}`. `routes` maps internal page IDs to paths relative to the repository root (home is empty). `toolRoutes` maps `damage`, `level`, `backup` to their paths. `shortcuts` is an ordered list `{label, items[]}`; each item is `{label, page, image, mode?, tool?, disabled?}`. `mode` selects a tier mode, `tool` selects a calculator; `disabled:true` is a noninteractive guide placeholder. `src/js/09-startup.js` reads this at startup and renders the home cards. All images must exist; route IDs must match the menu. `logo` records the original supplied logo used in the static shell.

Root opens Shortcuts; hero paths are exact hero names and share one address across Skills/Review/Build. `/tierlist` shares one address across all modes. `navInit`/`navRecord` store view state and scroll position in browser history. Old query/hash links canonicalize to the Beta paths. The `<base>` freezes the asset root before routing. `tools/build_routes.py` generates 39 committed `route/index.html` entry shells (including heroes and bare `/dungeons`); run it after source shell/routes/hero changes. The full check verifies those entries without writing. No server rewrite or deployment build is needed.

The old public tier renderer and preview gate are removed; former preview styles and controls apply everywhere. Legacy `HEROES[].tiers` stays as historical data; displayed profile ratings come from `TIER_LIST_V2.heroes[].overall`. Review prose remains David's pending rewrite.

### Text formats the page reads (keep them exactly)

- **Profile `karma`:** `Recommended Karma: <Signature> (signature) + <Second card>. Alternatives: <a>, <b>`. Karma names must match `KARMA_DATA[].name` exactly, or the hover card and the Karma-tab link won't find them.
- **Profile `gear`:** `Recommended Gear sets: 3 <Set> + 2 <Set>. Main stats: <stat> chest, <stat> legs. Substats: …`. Set names must match `GEAR_DATA[].name`.
- **Profile `role`:** `Role: <Main DPS|Sub-DPS|Support…>: <description>`. Its first words should match the hero's `role` in `HEROES`.
- **Skill `skill`:** a name ending in `(Lv.N)`, where N is the max level and sets the slider range. `(Lv.1)` gets no slider.
- **Skill `slot`:** a slot starting `MODE SWITCH` renders a mode heading. A slot containing `Mastery (passive)` gets no slider.
- **Skill `description`:** plain text with `\n` line breaks, copied from the in-game codex. Formatting is applied automatically when the page renders:
  - The number in `Attack Power N% Damage` is bold, and it's the only number the level slider changes.
  - Status words from `STATUS_ARCHETYPE`, and phrases like `Poison 2 stacks or more`, are bold in the archetype colour.
  - `[Bracketed names]`, Super Armor, Taunt, `%` values, seconds and `N times` are bold.
  - Any line starting `Activation Conditions` is red.

## Data rules

1. **Sources of truth:** hero skill data comes from the in-game codex; Karma stats, gear-set effects and the game's Recommended Combinations come from David's screenshots. If anything conflicts, the codex wins. Flag the conflict; don't guess.
2. **Never invent numbers.** Status mechanics are only partly measured (see `DAMAGE_TESTS` in `data/research.json`): Poison, Bleed, Burn and Shock tick 5 times (at 0, 2.5, 5, 7.5 and 10 s), for 50/75/100% of the first applier's Attack at 1/2/3 stacks (max 3). Frost doesn't tick (3 stacks Freeze the enemy, Frozen = +50% on hits); Airborne, Knockdown and Stun give +100% on hits; all hit bonuses add, with no cap (Stun + Knockdown + Airborne = ×4, measured 31 Oct 2026; see `DAMAGE_TESTS.findings`). The only calculated values on the site are clearly labelled:
   - **Skill levels below max:** Lv. 1 = max ÷ 1.75 times the measured multipliers (`SKILL_LEVEL_MULTIPLIERS`). Every level is measured; values can be 1 off the game because of rounding.
3. Codex values are post-patch 1.1.0. Patch 1.1.2 changed nothing in the balance. The 1.1.0 notes list every skill's Lv. 1 multiplier before and after; × 175 they equal the codex max-level % (124 of 126 exact; the notes swap the names of Alex's Auto and Jump attacks, Brandish and Dive Kick, so the codex names are kept).
4. **Dodge** (the `Dash` slot) can't be upgraded (always Lv.1) and does no damage: the hero's own skill window shows no damage value. The codex shows the jump attack's value next to it anyway. That number is kept out of the description and stored as the skill's `codexAttackPct`, which the page doesn't show. Don't put it back unless David confirms Dodge damage later in the game. Dash *attack* is a separate skill and does do damage.
   **Skill levels:** Auto, Dash and Jump attacks max at Lv.7; Skill, Ultimate, Special A and Special B at Lv.10; Mastery (passive) can't be levelled.
5. **Archetypes and their heroes:**
   - Venom (Poison): Johnny, Charlotte
   - Amplitude (Stun): Lute, Theresia
   - Crushing (Knockdown): Alex
   - Gale (Airborne): Reina, Eileen
   - Bloodburst (Bleed): Roxy
   - Blazeflame (Burn): Aria, Kalien, Kalsion
   - Frostbite (Frost): Dana, Cerese, Othello
   - Thunderbolt (Shock): Ornette, Sion, Tarte, Ryza
   - Breaker (Break): Castella, Astria

   Many heroes inflict Knockdown, but Alex is the only Crushing hero.
6. **Default build:** a 3-piece set matching the archetype, plus a 2-piece set chosen by `tools/hero_stats.py` (`HERO_BUILDS[hero].setChoice`). Since 28 Oct 2026 that's The Infiltrator for every damage build (about +0.4–1.6% over Battle Will), and Battle Will for the supports (Lute, Dana, Sion) and the tank. Exceptions to the 3-piece:
   - Castella and Astria: 3 Ruinsbreaker
   - Alex: 3 Earthshatterer

   Main stats and substats per slot are in `HERO_BUILDS` (see "Gear, builds and end-game stat totals" below). Karma: the signature first, then the best general card of the hero's own archetype.
7. The old Excel workbook (`DragonSword_Awakening_Master_Reference_Claude_Edit_27Oct_v2.xlsx`, kept on David's Google Drive) is **out of date**. Use `data.json` instead.

## Gear, builds and end-game stat totals

**`GEAR_MODEL` (added 10 Nov 2026; preview only).** Settings for the "Best Gear" box on the hero Build tab with `?tiers=new`, which replaces the Best Gear Sets, Best Main Stats and Recommended Endgame Stats boxes there. The box is the JS port of `tools/team_gear.py` (block between `/*GM-START*/` and `/*GM-END*/` in `src/js/04-gear-builds.js`; keep the two identical). Fields: `level` (gear +15), `defense` (the Enemy buttons: label, Defense, tooltip), `statuses` (the status tick boxes; `Other` = a status with no AAP substat, which still counts for All Status AAP), `physical` (statuses counted at 50% uptime when "Half the time" is on), `excludeSets` (Ballad of Life), `runeMix` (the rune mix used to rank set pairs: 3 Focus + 2 Amplification; the box then tries all 21 mixes of Focus, Amplification and Determination on the winning pair at the top Perfect values in `RUNES.seen`), `teamStatuses` (each main-team hero's default ticks; other heroes start with their own archetype's status). Every other input comes from `HERO_BASE_STATS`, `KARMA_DATA` (signature base Attack and A6 traits), `AWAKENINGS`, all `TITLES`, `GEAR_STATS` and `GEAR_DATA` (`twoBonus`, `threeBonus`).

**`GEAR_MODEL.account` (11 Nov 2026; offline account preset).** `{updated: "YYYY-MM-DD", awakenings: {heroName: integer 0..6}}` records David's last confirmed awakening levels for all 20 heroes; no missing-hero/A6 fallback is allowed. Signature ownership is derived from existing `KARMA_DATA[].signature` and `owned`, not duplicated in the account object. `tools/team_gear.py` and the browser parity cases use this account preset. It does **not** change the website's maximum-build defaults or a visitor's settings. Update the account record when David confirms changes and keep STATUS in step. The validator checks exact hero coverage, integer levels and recorded awakening limits. The shape update for this addition has exactly four new paths (account, awakenings, awakening value, updated).

**Gear rules (from David's testing; may change):**
- Main stat values depend on the upgrade level. Each substat has one fixed value.
- Green gear maxes at +6 with 2 substats, Blue at +9 with 3, Purple at +12 with 4, Orange at +15 with 5. Substats unlock at +3, +6, +9, +12 and +15.
- A stat **can** be both main stat and substat on the same piece (seen on Green, Blue and Purple, 30 Oct 2026). Substats on one piece are all different. Every slot can roll every main stat.
- Cooldown Reduction and Status Application Rate don't exist on armour. Don't recommend them.
- Helmet, Gloves and Boots have identical tables for now.

**How the page calculates the totals** (`endgameStats()` in `src/js/04-gear-builds.js`; all inputs are in `data.json`):
- Attack = (hero base + signature Karma base Attack + flat Attack from gear) × (1 + all Attack Power Up %). Defense and Max HP work the same way with Defense Up and Max HP Up.
- Every other stat is a plain sum: hero, Karma traits at Ascension 6, gear main stats at +15, and substats.
- Set bonuses (always-on and conditional) are calculated separately and shown in green next to the total, with a hover giving the source and the condition.
- Awakening stat bonuses (all six awakenings, from `AWAKENINGS[hero].list[].effects`) are added after the set bonuses and shown in purple, with a hover naming the awakening.
- Only the signature Karma counts; the second Karma doesn't.
- Titles the viewer ticks on the Titles tab are added last and shown in gold (flat to flat, % to the % pool).
- **Live gear optimiser** (`liveBuild()`, `optBest()`, `optDamageIndex()` in `src/js/04-gear-builds.js`): when ticked titles add Attack, Attack Power Up, Crit Rate or Crit Damage, Damage and Support builds are re-optimised in the browser. It's an exact port of `tools/hero_stats.py` (verified: with no titles it reproduces every stored build), with the titles added to the bonuses. The 2-piece set stays the stored `setChoice`. Changed pieces get a gold frame. Keep the two in step: if the Python optimiser changes, change the JS port too.

**How `HERO_BUILDS` was chosen** (by role and team position, after checking skill text):
- **Damage builds** (Main DPS, Sub-DPS and the enablers Reina and Kalien): every combination of Attack Power Up, Crit Rate and Crit Damage main stats was tried. The one with the highest Attack × (1 + Crit Rate × Crit Damage) won. The calculation counts all six awakenings' stat bonuses and the 2-piece set's always-on bonus, caps Crit Rate at 100% and leaves out 3-piece bonuses, except Blazing Flames' Crit Rate for Aria, Kalien and Kalsion (they apply Burn with almost every skill). Spare substat slots get Defense Ignore, then the hero's own status Additional Attack Power.
- **2-piece set** (damage builds): the mains are re-optimised for Battle Will, The Infiltrator, and the set of every status one of the hero's skills needs (Azure Gale, Earthshatterer, Holy Arbiter, Ruinsbreaker). A status set's +15% Additional Damage only counts on hits from skills that need that status. Those hits are weighted for their status bonus (`DAMAGE_TESTS`), and different statuses' Additional Damage is assumed to add (the cautious case, untested). `setChoice` stores the comparison, including what status sets would give if the bonuses multiply. The profile `gear` sentence and `build.sets` are rewritten to match by `--write`.
- **Support builds** (Lute, Dana, Sion): Max HP Up chest and Defense Up legs, damage on the other three slots. Their heals and buffs are % of max HP or flat %, so their own stats can't raise them.
- **Tank build** (Alex): Max HP Up and Defense Up in every slot, with HP, Defense and crit-resistance substats.

**Observations not used in the totals yet** (in `HERO_STAT_MODEL.observations`):
- every status resistance is 50, at any level;
- Titles add account-wide passives to every hero. Base stats exclude them; the totals add the titles each viewer ticks (see `TITLES`). The in-fight stat panel includes the owned titles, so subtract them from panel readings ([GAME_MATH.md](library/GAME_MATH.md) 2.2).
- displayed stats are rounded down.

## Procedures

1. **Measured Lv.70 stats for a hero:** put them in `HERO_BASE_STATS[hero]` (titles taken off), set `estimated: false` and `profile`, then run `tools/hero_stats.py` (inspect, then `--write`). If the hero matches none of A, B, C, D, add a new profile to `HERO_STAT_MODEL.measured` and tell David.
2. **Gear tables or rules change:** update `GEAR_STATS` (and `valueSources`), run `tools/hero_stats.py --write`, and check the JS optimiser still reproduces every stored build.
3. **Recalculating a damage build:** try all 3⁵ main-stat combinations as described above, or ask David before hand-editing.
4. **Team-aware builds** ("with Eileen"): ask David first. Brave One and Vanguard Banner only buff heroes standing in their circles, and builds sit well below 100% Crit Rate, so her +20% isn't wasted.
5. **A new, renamed or moved key, or a new data file:** describe it in the key table above, update the code that reads it, run `python3 tools/check_shape.py --update` and read every difference it prints (each must be one you meant), and commit `tools/data_shape.json` with the data. New entries under existing keys need nothing.

Import is exact replacement of these five sections, never a merge: null sections remove the corresponding key. Files larger than 1 MiB, unsupported formats/versions, incomplete sections, unknown entries/fields and malformed nested settings are rejected before writing. Opening a file only shows a review; Cancel writes nothing. Browser preferences such as tag visibility and the selected Tools tab are untouched.

Before restoring, `dsw.progressUndo.v1` saves all five original raw values (including absent keys). A failed write attempts rollback, and a successful restore reloads the page to refresh cached title selections/calculator state. `Undo last restore` survives reload on the same browser and restores the previous raw values. This is one recovery copy, replaced by the next restore, not an extra exported/cloud backup. A transient sessionStorage notice reports restore/undo after reload. Keep an exported file outside browser storage for moving devices or surviving browser clears.

This is a visitor-created file with runtime validation, not an additional repository data file in `check_shape.py`. If storage formats change, update the backup version/validation and its browser tests deliberately. `progress_backups()` in `tools/check_site.py` covers real download/upload, review/cancel, reload, exact restore/undo, invalid files, missing/empty sections, unrelated-key preservation and mid-write failure rollback at 1400 and 390 px.
